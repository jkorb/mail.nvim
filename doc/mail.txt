*mail.nvim*  Plain-text email editing for Neovim

SETUP                                                        *mail-setup*

Install this repository with your plugin manager, and call setup before opening
mail or when the mail filetype loads. Neovim detects .eml files and common
Mutt/NeoMutt temporary files; use :setfiletype mail for other filenames.

Defaults: >lua
  require("mail").setup({
    cmp_contacts = true, -- register completion for contacts and phrases
    contacts_eval = nil,
    contacts_timeout = 3000, -- milliseconds
    contacts_only = true, -- Blink: only contacts during address completion
    phrases = {
      best = "Best,\nJohannes",
      groetjes = "Groetjes,\nJohannes",
      sounds = "Sounds good to me.",
      thanks = "Thanks for your help.",
      followup = "Just following up on my previous email.",
      attached = "Please find the document attached.",
    },
    fold_quotes = true,
    draft_check = true,
    image_picker = "nnn", -- executable name or path, without arguments
    image_keymap = "<localleader>mi", -- Normal mode; false disables the shortcut
    view = {
      enabled = true,
      quote_char = "┃", -- use "│" for a thinner bar
      keymap = "<localleader>mv", -- Normal mode; false disables the shortcut
    },
    treesitter = true,
    parser = nil, -- preserve an existing nvim-treesitter parser registration
  })
<
Neovim 0.11 or later is required. Setup may be called again to replace options.
Navigation and contact completion work without Tree-sitter.

GRAMMAR                                                      *mail-grammar*

The custom mail grammar is distributed separately: >lua
  require("mail").setup({
    parser = { url = "https://github.com/jkorb/tree-sitter-mail" },
  })
<
A local checkout works too: >lua
  require("mail").setup({
    parser = { path = vim.fn.expand("~/path/to/tree-sitter-mail") },
  })
<
Load nvim-treesitter before mail.nvim, then run :TSInstall mail. The main branch
of nvim-treesitter requires Neovim 0.12+; its legacy master branch works with
0.11. Both parser registration APIs are supported. For a remote grammar you can
also set parser.revision to a commit hash or parser.branch to a branch name.

mail.nvim starts the mail highlighter when a mail buffer opens, including
buffers open when setup runs. Restart Neovim after installing or updating a
parser. :checkhealth mail checks the installed parser and query compatibility.
If a query reports an invalid node type, rebuild the parser or run :TSInstall!
mail, then restart Neovim. :TSInstall mail skips an already installed parser;
:TSUpdate mail may also skip a local grammar without a pinned revision.
Custom queries must also use node names from the current grammar (for example,
body instead of the older text_block).

:TSInstall markdown markdown_inline enables Markdown inside the body.

VIEW                                                         *mail-view*

The mail view is enabled by default. It displays colored quote bars, underlined
links, and aligned Markdown tables with borders. Markdown emphasis and link
syntax are concealed using Neovim's Tree-sitter queries. The draft itself is
never changed. This needs Tree-sitter; install mail, markdown and markdown_inline.

The cursor line shows its source. Moving into a table reveals its source layout;
moving out restores the borders. Tables also show their source during Visual
selection. If a draft is open in several windows, a table being edited in one
window shows its source in all of them.

Use :MailViewToggle or <localleader>mv (usually \mv) to toggle the view for the
current draft. The shortcut is buffer-local and respects existing mappings.
To disable the view by default: >lua
  require("mail").setup({ view = false })
<
For thinner quote bars or a different shortcut: >lua
  require("mail").setup({
    view = { quote_char = "│", keymap = "<localleader>v" },
  })
<
view = true restores the defaults. Set view.keymap = false to leave the shortcut
unmapped. Quoted mail uses six colors; deeper quotes use level six. Highlight
groups are MailQuote1 through MailQuote6, MailLink, MailTableHeader and
MailTableBorder; define them in your colorscheme to change their appearance.

While a mail buffer is displayed, the view sets conceallevel=2 (0 when disabled)
and concealcursor="". Previous window settings are restored when leaving mail.
Other filetypes and their Tree-sitter queries are unaffected.

Code fences and their language labels stay visible, including unfinished fences.
Quoted code keeps its outer quote bars; > characters inside the code stay literal.
With mini.pairs, typing three backticks produces three, without an extra paired
backtick. Inline code still pairs normally. This applies only to mail buffers
and preserves custom backtick mappings.

FOLDING                                                      *mail-folding*

By default, the most recent quoted reply (one > prefix) stays open. Older
history nested with >> or deeper starts folded. This uses quote depth; messages
that put every historical reply at the same depth cannot be distinguished.
The message text is unchanged, and code fences are excluded from quote detection.

Use zo to open a fold, zc to close it, and zR to open all folds. Manually opened
folds are preserved when switching windows or returning to the draft.
Set fold_quotes = false to keep your existing folding configuration.
Folding works independently of MailViewToggle and does not require a parser.

CONTACTS                                                     *mail-contacts*

Enable the source named cmp-contacts in nvim-cmp: >lua
  require("cmp").setup.filetype("mail", {
    sources = { { name = "cmp-contacts" } },
  })
<
Or add it to blink.cmp through blink.compat: >lua
  -- blink.compat must be installed and its cmp impersonation enabled.
  require("blink.compat").setup({ impersonate_nvim_cmp = true })
  require("blink.cmp").setup({
    sources = {
      default = { "contacts" }, -- append to your existing sources
      providers = {
        contacts = {
          name = "cmp-contacts",
          module = "blink.compat.source",
        },
      },
    },
  })
<
With blink.cmp, address values and body @lookups use only the contact provider
by default. Elsewhere, your existing sources are preserved, including any
mail-specific list or function. Set contacts_only = false to keep all sources
during contact completion.
This works with providers named cmp-contacts or an alias such as contacts above;
no global completion changes are needed. It also applies to folded address
lines and Reply-To/Resent headers. The source must still be configured in Blink.
For nvim-cmp, source selection follows your cmp.setup.filetype or
cmp.setup.buffer configuration.

Set contacts_eval to a command that returns a JSON array of name/address maps.
For example: >
  [{"Alice Smith":"alice@example.org"},{"":"bob@example.org"}]
<
The placeholder {input} is replaced with the current recipient being typed.
Display-name quotes are removed for searching; inside <...>, the lookup receives
the address being typed. Selecting a contact replaces the whole recipient.
A string command runs in Neovim's shell; the plugin shell-escapes the input.
Leave {input} unquoted in the template. An argument list avoids the shell: >lua
  require("mail").setup({
    contacts_eval = { "/path/to/fetch_contacts", "{input}" },
  })
<
The command can omit {input} and return all contacts. Names containing quotes or
backslashes are escaped for insertion. Empty names insert a bare address.
Malformed entries and duplicate suggestions are ignored. Failed commands,
invalid JSON and timeouts return no suggestions; older requests are cancelled
when another begins. No lookup runs from :checkhealth mail.

Completion is available in To, Cc, Bcc, From, Sender, Reply-To and their Resent-
variants, including empty fields and folded recipient lists. It stays out of
header labels and the subject. Completing a name that itself spans multiple
lines is unsupported. contacts_timeout defaults to 3000 milliseconds.

In the body, type @ followed by a name to look up a contact (for example,
"Ask @Alice"). Selecting a contact inserts @"Alice" <alice@example.org>, keeping
the @, name and address. The lookup ends at whitespace or punctuation.
An @ inside an existing address does not trigger contact completion.

PHRASES                                                      *mail-phrases*

Type ! at the start of a body line or after whitespace to complete a phrase.
For example, !be offers !best; accepting it inserts two lines: >text
  Best,
  Johannes
<
The !shortcut is replaced completely. Sign-offs use literal text and newlines;
there are no snippet placeholders. Other defaults are !groetjes, !sounds,
!thanks, !followup and !attached. Quoted text, code and headers do not trigger
phrases. Normal punctuation such as "Hello!" and Markdown images are unaffected.

Phrases use the same cmp-contacts source as contacts, without needing a
contacts_eval command. With Blink, only that source is active during a phrase
lookup; normal sources resume afterwards. With nvim-cmp, your existing source
configuration applies. cmp_contacts = false disables both kinds of completion.

Set phrases to replace the entire list, including the default sign-offs: >lua
  require("mail").setup({
    phrases = {
      best = "Best,\nYour name",
      thanks = "Thanks for your help.",
    },
  })
<
Shortcut names contain letters, digits, underscores or hyphens, without !.
Set phrases = {} to disable phrase completion while keeping contacts.

DRAFT CHECKS                                                 *mail-check*

:MailCheck reports empty subjects, missing recipients, duplicate recipients,
a missing header/body separator, unfinished placeholders (TODO, FIXME,
[insert ...], <++>), unexpanded phrase shortcuts, and missing local image files.
Quoted history and code are skipped for body checks. Placeholders in signatures
are skipped too. Relative image paths are resolved beside the draft file, or
against the working directory for unnamed drafts. Remote images are not fetched.
This checks the draft text; it does not inspect NeoMutt's attachment list.

With draft_check = true (the default), typed :q and :wq commands run these checks
before executing. If something is found, choose Keep editing or Leave anyway.
Keep editing is the default and leaves unsaved edits intact. A clean draft
continues without a prompt. Ordinary :w saves are unaffected.

Checks also cover :q!, :x, :qa, :wqa, command chains such as :w | q, and the
buffer-local ZZ/ZQ shortcuts when those keys are not already mapped. Commands
that exit the whole editor check all loaded mail drafts. :cquit remains available
to abort editing with a failure exit status for NeoMutt.

The guard uses CmdlineLeave: Neovim's QuitPre event cannot reliably cancel a
quit. Direct programmatic quits and existing <Cmd> mappings bypass CmdlineLeave.
Route custom quit mappings through the checked Lua entry point: >lua
  require("mail.check").quit("wq")
<
Set draft_check = false to disable automatic checks; :MailCheck still works.
Findings appear as buffer diagnostics and are cleared when you edit the draft.

IMAGES                                                       *mail-images*

Use :MailImage in the body to open nnn in a floating terminal. The buffer-local
Normal-mode shortcut is <localleader>mi (usually \mi). Existing mappings are
left alone. Install nnn separately; image_picker can point to its executable.
Set image_keymap to another key sequence or false to disable the shortcut.

The picker starts in Neovim's working directory. To start elsewhere: >
  :MailImage ~/Pictures
<
Press Enter on an image to pick it. Space selects multiple images; Enter
finishes the selection. Ctrl-C cancels, including after selecting files.
Quitting nnn with no selection also cancels. Enter a description for each image;
the default is its filename without the extension. Cancel a description prompt
to leave the draft unchanged.

The picker inserts Markdown at the cursor, for example: >
  ![A diagram](</home/me/Pictures/diagram%20(final).png>)
<
Paths are absolute and escaped; descriptions are treated as literal text.
Multiple images occupy separate lines. Directories, unreadable files and
files without a recognized image extension are rejected.

Use this with a Markdown-to-HTML mail workflow. Your mail renderer must embed
local images as inline attachments; mail.nvim inserts the Markdown and does
not create MIME attachments. Plain-text mail keeps the link.

NAVIGATION                                                   *mail-navigation*

On first opening a mail buffer, a nonempty In-Reply-To header places the cursor
at the first body line. Other messages start at the To value. Switching buffers
or rerunning setup preserves the cursor. Initial placement stays in Normal mode;
press A to append to an empty header value.

These buffer-local commands jump without changing the message: >
  :MailTo       :MailCc       :MailBcc       :MailSubject       :MailBody
<
Missing fields are left alone. No navigation keys are mapped. For example: >lua
  vim.api.nvim_create_autocmd("FileType", {
    pattern = "mail",
    callback = function(event)
      vim.keymap.set("n", "<localleader>b", "<cmd>MailBody<cr>", { buffer = event.buf })
    end,
  })
<
Lua callers can use require("mail.navigation").jump("body") or a lowercase
header name. It returns true on success and false when the target is absent.

TESTS                                                        *mail-tests*

Run `make test` from the repository. For grammar/query integration checks, set
MAIL_NVIM_PARSER to an absolute path to the compiled mail parser: >
  MAIL_NVIM_PARSER=/path/to/mail.so make test
<
Tests use synthetic contacts and temporary Neovim state under tmp/.
Set MAIL_NVIM_NNN to the nnn executable to test real image selection and
cancellation in a terminal as well as the image picker's other checks.

`make test-integration` also tests real dependencies. Set MAIL_NVIM_CMP to an
nvim-cmp checkout and/or MAIL_NVIM_BLINK_COMPAT to a blink.compat checkout.
Set MAIL_NVIM_BLINK to a blink.cmp checkout to also test source selection.
To test parser installation, set MAIL_NVIM_TREESITTER to an nvim-treesitter main
checkout and MAIL_NVIM_GRAMMAR to a disposable copy of the grammar. The installer
builds inside that copy and installs under tmp/installed. All paths are absolute.
MAIL_NVIM_MARKDOWN_PARSERS can point to a directory containing markdown.so and
markdown_inline.so to check highlighting inside the body too. Together with
MAIL_NVIM_PARSER, it also enables `make test` checks of the mail view, including
rendering in an attached Neovim UI.
Set MAIL_NVIM_MINI_PAIRS to a mini.pairs checkout to include real typing,
backspace and undo checks for code fences.
Add MAIL_NVIM_LAZYVIM to test with LazyVim's pairing configuration too.
